# M0 Result — Pointer-Warp Feasibility

Date: 2026-08-10  
Environment: Fedora Linux 44, GNOME Shell 50.3, Mutter 50.3, Wayland

## Verdict

**PASS.** Continue Phase 1 with a GNOME Shell extension for pointer observation
and warping. The `evdev/uinput` fallback is not required at this gate.

## Automated evidence

Command:

```bash
./scripts/run-headless-spike.sh
```

The test ran the packaged extension inside an isolated GNOME Shell with a
1280x720 monitor and a 1920x1080 monitor. It injected absolute pointer motion,
verified that the extension's global Clutter event filter observed the event,
then called `Clutter.Seat.warp_pointer()` through `WarpToNextMonitor`.

Observed result:

```json
{
  "passed": true,
  "activeMonitors": 2,
  "observedMotionEvents": 1,
  "targetIndex": 1,
  "destination": {"x": 2560, "y": 360},
  "pointer": {"x": 2560, "y": 360}
}
```

The requested destination and compositor-reported pointer position matched
exactly.

Geometry command:

```bash
npm test
```

Result: 6/6 tests passed, covering negative desktop coordinates, monitor
selection, list wrapping, rectangle centers, proportional physical-height
mapping, and rejection of points outside a target physical edge.

## Technical findings

- `Clutter.Seat.warp_pointer()` is callable from a GNOME 50 Shell extension.
- `Clutter.Event.add_filter(global.stage, callback)` observes injected global
  pointer motion; `global.stage::captured-event` did not observe the headless
  injected event and was replaced.
- A second headless monitor can be supplied through a tiny process wrapper,
  avoiding an optional `libmutter-test` dependency.
- GNOME 50 does not discover a brand-new local extension UUID in an already
  running Wayland session. The first live enable therefore requires the next
  login; subsequent developer builds can use the isolated test tool.
- The debug D-Bus interface is M0-only and must be removed or secured before a
  production build.

## Known test-harness warning

The synthetic virtual-pointer event produces one Clutter critical message about
a missing event actor in the headless harness. The event is still delivered and
the assertion is not seen on normal hardware input. Treat this as a harness
warning and re-check it during the live-session test.

## Gate decision

M0 is complete for technical feasibility. Proceed to M1 monitor discovery and
mapping. Keep a live-session checklist item for hardware motion, drag state, and
disable/recovery behavior after the next login.
